# Privacidade, localização e infraestrutura — validação

## Entrega

Política e canal públicos, identificação/contato autorizados pelo usuário, escolhas opcionais de Maps e métricas, geolocalização por ação explícita, informações práticas editáveis de eventos e distinção publicador/organizador. Inventário e procedimento de retenção/atendimento em `docs/privacy-operations.md`.

## Verificações aprovadas

- `npm run lint`: sem avisos/erros.
- `npx tsc --noEmit --incremental false` e `npx tsc --project tsconfig.server.json`.
- `npx prisma generate` e `npx prisma validate`.
- `npm run build` final, incluindo páginas públicas e API de revogação de cookies. Uma repetição anterior falhou por EPERM em `.next`; o build final fora do sandbox passou.
- `node scripts/verify-privacy.cjs`: negativa padrão antes de acesso ao banco, origem, opt-in, limpeza limitada aos cookies de contagem e proteção contra sobrescrever preferência mais recente.
- `npm run test:features`, `npm run test:account-removal`, `npm run test:security`, `npm run test:site-improvements`, `npm run test:community`, `npm run test:event-chat` e `node scripts/verify-event-draft-recovery.cjs`.
- API do build local confirmou `/api/socket` disabled/false e POST de métrica sem cookies retornou measured=false. A requisição inicial com Origin 127.0.0.1 foi recusada pela origem canônica local; a verificação sem Origin, própria do cliente de teste, confirmou bloqueio de medição. Teste isolado também exige recusa de origem estrangeira e limpeza com Origin obrigatório.

A tipagem inicial foi bloqueada por três junctions extraneous em `node_modules/@types` apontando a dependências temporárias incompletas (stats.js, three, webxr), ausentes do package.json/lock. Foram isoladas, sem apagar seus destinos, em `output/privacy-broken-type-links`. Nenhuma dependência foi adicionada ao projeto. O package.json já modificado pelo usuário foi preservado.

Dois harnesses preexistentes precisaram de correções: o loader de serviços não resolvia import relativo; a fixture Socket.IO não reproduzia effectiveRole do handshake e emitia aviso de papel antes de testar expiração. As assertions de autorização/expiração foram mantidas. Os testes de filtros foram adaptados para exigir a ação explícita e recusar respostas antigas, mantendo as garantias de concorrência.
